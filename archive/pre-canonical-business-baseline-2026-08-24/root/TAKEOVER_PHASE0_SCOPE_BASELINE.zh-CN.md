## 1. 用途

本基线固定当前项目接手工作的执行边界，防止把未来生产计划、历史完成声明和已有源码误解为当前本地交付的执行授权或完成证据。

“接手阶段 0”是一个审计和执行对齐阶段，与历史 PRD 中的 Phase 0（`P0-01` 至 `P0-12`）不是同一批工作。已有的 P0 契约、数据库迁移、测试和实施记录都是需要核验的输入；它们不会被自动重做，也不能自动认定为运行时已完成。

## 2. 权威来源和证据顺序

当不同来源发生冲突时，按以下顺序处理：

1. 用户最新的明确指令。
2. `txgj-doc/PRD_IMPLEMENTATION_DECISIONS.md` 中已接受或已修订的决策。
3. `txgj-doc` 中已经采纳的阶段修订和技术决策。
4. `txgj-doc/PRD_PHASE_IMPLEMENTATION_PLAN.md` 中的开发票据依赖和验收契约。
5. 当前代码仓库中与版本绑定的实施记录、契约、数据库迁移、测试和已签署证据。
6. 研究文档和历史设计归档。

产品文档决定已经批准的业务含义；当前源码和实际测试、运行证据决定真实的实现状态。仅有源码文件或 `implemented_local` 状态，不足以证明运行时、浏览器、数据库、云端或发布已经完成。

## 3. 当前本地 Release 1 范围

### 包含范围

- 使用确定性合成身份和业务数据的本地 Next.js ERP，以及 `/api/v1/**` 业务 API。
- 本地服务端会话和仅供开发使用的角色登录；离开明确的本地运行模式后必须被禁用。
- Student、Guardian、ServiceCase、16 字段评估、SchoolTarget、Task、Document、站内 Notification 和 Audit 工作流。
- 使用已提交的非 PII 学校数据，完成经过验证的学校快照读取、筛选、审核决定、工单和受控案件重建。
- 严格字段白名单、禁止列出或下载文件的受限只读 External Portal。
- 平台侧“推进中案件数量”和不透明的合同参考值；不产生应付金额或会计流程。
- 在明确的本地 Colima/Docker Compose 配置下运行 PostgreSQL 17、LocalStack S3/SQS 行为和 ClamAV。
- 每个已批准开发票据运行聚焦测试；里程碑级广泛检查需要单独批准。

### 不包含范围

- AWS、Cloudflare、Vercel、DNS、Terraform 执行、生产部署、生产账号或预算工作。
- 真实 Cognito、RDS、S3、SQS、KMS、生产密钥或真实通知发送。
- 真实 Student、Guardian、ServiceCase、文件或其他私密业务数据。
- Neon 到 RDS 的数据迁移、生产 backfill、首个真实案件发布、试点、第二组织启用或生产支持访问。
- 自动爬虫调度或由爬虫自动提交前端部署版本。
- AI/知识库流程、外部 Email/SMS/WhatsApp、非 K12 流程、Portal 公开注册或写入，以及多租户启用。
- 收费公式、按比例计费、发票、收费通知、付款、退款、税务或会计。

未来的 AWS 香港文档继续作为生产目标和安全约束。它们只是延期执行，并没有被本地运行目标取代。

## 4. 不可削弱的执行约束

- `local-synthetic` 和 `production-aws` 组合必须明确且互斥。本地适配器在本地模式以外必须 fail closed（拒绝启动或拒绝执行）。
- 不能为了本地开发方便而削弱生产区域、隐私、授权、审计、租户隔离、文件隔离扫描、幂等性和数据库迁移只追加不重写等约束。
- `/api/v1/**` 是目标业务 API。现有非 v1 路径和 Neon 路径属于需要迁移的技术债，不是目标设计。
- 在经过验证的真实替代方案出现前，保留 Mock 和 preview 实现；它们必须在需求追踪矩阵中明确标注。
- 未来范围的源码可以继续保存在仓库中，但在 Release 1 中必须从导航隐藏或在运行时禁用。
- 本基线不代表已经授权提交、推送、广泛测试、安装、启动服务、执行数据库迁移、外部操作或部署。

## 6. 已知冲突及当前处理方式

| 冲突 | 当前处理方式 |
| --- | --- |
| 历史 PRD Phase 0 与接手阶段 0 | 保留历史开发票据；接手阶段 0 只负责核验现状并重新安排后续顺序。 |
| AWS 香港生产计划与本地优先交付 | AWS 继续作为未来生产目标；当前只授权本地合成数据工作。 |
| 实施记录与实际可运行行为 | 每种完成声明都必须有与之匹配的当前源码、聚焦测试、数据库、浏览器或运行时证据。 |
| `/api/v1/**` 契约与旧 `/api/cases`、Neon 服务 | v1 是目标；旧路径作为有明确退出条件的迁移技术债处理。 |
| 仅支持生产的配置保护与本地 PostgreSQL/LocalStack | 后续增加独立且 fail closed 的本地组合层；不放宽生产保护。 |
| 当前 crawler 快照与 `crawler-handoff/v1` 验证器 | 当前快照保持只读；启用新验证路径前，先定义转换或重新发布证据。 |
| 未来 AI/知识库、多租户源码与 Release 1 范围 | 源码保持休眠并从导航和运行时禁用；文件存在不等于功能已获授权。 |
| `erp-frontend/` 等历史工作区路径 | 相对于当前 `Tianxingguoji` 仓库解析，不重建旧工作区目录结构。 |
