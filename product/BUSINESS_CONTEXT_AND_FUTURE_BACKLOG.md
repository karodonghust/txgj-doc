## 2. 待业务负责人确认的历史背景

2026 年 6 月的评估描述了以下业务背景。这些信息具有产品研究价值，但尚未在当前决策台账中全部确认为现状：

- 机构服务中港跨境教育客户，历史上通过银行、保险等合作渠道取得转介。
- 当时约有 30 个并行跟进的客户或申请项目，团队主要依赖创始人和兼职人员交付。
- 服务跨度曾被描述为从 K12 到本科、硕士；当前 Release 1 已明确只启用 K12。
- 客户对响应速度、专业报告、数据准确性和进度透明度有较高要求。
- 创始人的选校、面试和文书经验被视为重要但难以规模化的知识资产。

在引用上述数字、渠道或客户特征前，产品负责人必须确认它们在当前时间仍然准确。

## 3. 历史痛点与 Release 1 映射

| 历史痛点 | 当前 Release 1 处理方式 | 状态 |
|---|---|---|
| 学校招生信息分散、更新容易遗漏 | 不可变 crawler 发布快照、审核队列、学校治理和来源追踪 | 已纳入，但自动调度未接通 |
| 学生和家庭信息散落 | Student、Guardian、ServiceCase 和 Assessment 领域 | 已纳入 |
| 依赖人脑追踪申请节点和截止日期 | SchoolTarget、Task、Dashboard 和站内通知 | 已纳入 |
| 兼职人员可见范围过大 | 角色、capability、case scope、Contractor 工作区和 RLS | 已纳入 |
| 家长缺乏受控的进度视图 | 受限、只读 External Portal | 已纳入 |
| 选校报告主要依赖 Excel，呈现效果有限 | 当前 selector 只有浏览器打印/PDF 预览 | 部分覆盖，专业报告未纳入 |
| CV、申请表和报告排版耗时 | Release 1 没有文档生成引擎 | 延后评估 |

## 4. 未来产品候选

以下项目是候选 backlog，不是已批准需求。

### FTR-001：专业选校报告

目标：根据已确认的学校目标、来源和顾问评语生成品牌一致的只读报告。

进入需求设计前必须决定：

- 报告接收人和允许字段；
- 报告是否属于案件文件及其保留策略；
- 顾问评语的审批和版本规则；
- PDF 与网页版本的权威关系；
- 下载授权、水印、审计和撤销方式。

### FTR-002：CV 与申请材料生成

目标：用经过批准的模板减少重复排版工作。

进入需求设计前必须决定：

- 支持的学段、材料类型和模板所有者；
- 哪些字段可自动填入，哪些必须人工确认；
- 照片、履历和敏感材料的香港驻留、权限及保留；
- 生成文件的版本、校验、审批和回滚规则。

### FTR-003：外部通知与沟通集成

目标：在任务、截止日期或学校目标状态变化时提供受控提醒。

进入需求设计前必须决定：

- 获准使用的邮件或企业通讯渠道；
- 消息中允许出现的数据；
- 同意、退订、重试、失败和审计规则；
- 微信等跨境通道是否符合数据驻留和隐私要求。

### FTR-004：受治理的知识助手

目标：将已批准的内部方法、模板和案例知识用于顾问辅助，而不是自动作出申请决定。

进入需求设计前必须决定：

- 知识来源、审阅人、版本和失效流程；
- 学生或案件数据是否允许进入模型；
- 模型、推理、日志和索引的数据区域；
- 提示词注入、错误建议、引用、人工复核和关闭开关；
- 如何将完整案例与可复用知识分离。

### FTR-005：冲刺／匹配／保底推荐

目标：在人工选校流程中提供可解释的候选分组。

进入需求设计前必须决定：

- 学生评分和学校要求是否有可靠、版本化的业务数据；
- 推荐属于规则结果、统计结果还是顾问判断；
- 历史案例是否具备合法、无偏且可比较的样本；
- 解释、人工覆盖、审计和效果验证方式；
- 推荐不得被表达为录取概率保证。

### FTR-006：非 K12 申请类型

目标：评估本科、硕士或其他申请类型是否应进入独立产品阶段。

进入需求设计前必须先定义独立的评估字段、申请状态、材料、截止日期、参与角色和合规边界，不能直接复用 K12 规则。

## 5. 不继承的历史技术结论

以下内容只作为历史研究记录保留，不构成当前建议：

- 使用 Appsmith 或 Budibase 构建主 ERP；
- 使用 Supabase 作为当前权威生产数据库；
- 使用 ScrapeGraphAI 或 LLM 绕过验证码和网站控制；
- 使用 n8n 作为当前业务状态权威；
- 使用 Dify、DeepSeek 或任何特定模型处理客户数据；
- 使用 WeasyPrint 或 Puppeteer 作为已批准的报告引擎；
- 历史成本、外包价格、科技券比例和自动化收益预测。

如未来重新评估这些能力，必须基于届时的官方资料、数据分类、许可条款、可维护性和实际测试重新决策。

Release 1 本地版本验收完成前，不启动本文件中的未来候选。届时按业务价值、数据风险、依赖和验证成本逐项建立独立 PRD，不把多个候选打包成一次技术集成。
