## BR-075 内部账号邀请邮件

状态：`confirmed`

Email 模块只服务于内部账号管理。它不提供公开注册，也不发送 Guardian 或
Student 的外部业务通知。

### 发送边界

- 只有 Founder 发起的用户邀请可以触发账号确认邮件。
- 收件人来自邀请记录中的规范化内部邮箱；浏览器不能直接指定任意发件人或投递结果。
- 邮件只包含一次性确认链接、有效期和初始化说明。
- 邮件不得包含密码，不得在确认链接之外单独展示 token，也不得包含学生、Guardian、Case、学校或文件信息。

### 可靠性与记录

- Email 模块负责模板渲染、传输适配、幂等键和投递回执。
- 数据库只保存确认 token 的哈希和安全的投递回执，不保存 token 明文。
- 确认凭证放在链接的浏览器片段中，不进入初次 HTTP 请求、服务器访问日志或 Referer。
- 相同邀请和相同发送操作不得重复产生不可控副作用。
- 发送失败时邀请仍保持可重试的未完成状态；重发必须使旧链接失效。
- 开发和测试可以使用确定性假传输；Production 必须配置受控 SMTP 或事务邮件传输。

### 与认证的关系

邮件只是邀请交付渠道，不是身份认证平台。用户点击链接后由 Identity
模块验证一次性 token、设置初始密码、初始化个人资料并创建内部会话。

### Resend 配置管理

- 项目通过代码依赖集成 Resend，不依赖 Vercel Marketplace 或其他部署平台的集成。
- 只有当前具有 `Admin` 基础角色的内部用户可以查看配置状态、保存或轮换本组织的 Resend API Key 和发件人资料；仅有 `Founder` 角色不自动获得该权限。
- API Key 必须加密保存，浏览器、读取接口、日志和审计均不得返回明文或密文；页面只显示是否已配置、发件人资料及非敏感更新时间。
- 保存新 API Key 表示轮换并替换本组织的当前配置，不保留可重新启用的旧明文密钥。
- 发件人资料包括发件邮箱和可选发件名称；实际可投递范围仍受 Resend 已验证域名及账号权限约束。
- 配置变更必须记录操作组织、操作人和追加式审计，但审计内容不得包含 API Key。
- 运行环境仍需持有独立的服务端加密主密钥；该主密钥不是 Resend API Key，不能通过业务页面读取或设置。

### 邮件模板管理

- 只有当前具有 `Admin` 基础角色的内部用户可以查看和修改本组织的邮件模板；仅有 `Founder` 角色不自动获得该权限。
- Release 1 只提供一种模板：内部使用者注册邀请模板，不预建其他邮件模板。
- Admin 可以修改邮件主题和正文说明；页面必须同时显示当前内容和预览。
- 一次性确认链接、链接按钮、有效期和账号初始化安全说明由系统固定生成，不允许模板管理页面删除、改写或注入这些安全字段。
- 模板正文以纯文本保存，生成 HTML 邮件时必须转义，不接受管理员输入的原始 HTML、脚本或外部追踪代码。
- 模板修改必须递增当前版本号，并记录组织、操作人和追加式审计；读取和发送邮件时均使用本组织当前版本。尚未保存自定义版本时使用系统内置默认模板。

## BR-015 试用等级的系统配置范围

状态：`confirmed`（试用实施）

显式设置试用等级的成员中，仅 Founder 可管理内部邀请、邮件凭据和安全配置，L1/L2/L3 均不可操作。旧 Admin-only 配置限制在该试用范围为 `superseded`，不把旧 Admin 自动映射为 L1 或 Founder。原秘密加密、不可回显、一次性链接与投递回执规则继续适用。
